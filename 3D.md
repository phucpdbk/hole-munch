# 3D rendering

The game now uses a Three.js orthographic scene with a tilted follow camera.
Buildings, trees, traffic, people, street furniture, fountains and common animals
use lit 3D geometry. Swallowed models shrink, tilt and sink below the ground.
Gameplay coordinates, scoring, progression and saved data remain unchanged.

Bosses, landmarks and some specialty props still use the existing artwork as
camera-facing sprites in the 3D scene. This is an initial 3D conversion, not a
complete replacement of every asset. Cosmetic skins and world effects are drawn
onto a transparent ground plane; the HUD stays on the existing overlay canvas.

Three.js 0.180.0 is pinned in package.json. Its two browser modules and MIT license
are included under src/vendor so development, ZIP packaging and native web builds
work without a CDN. When upgrading Three.js, replace both vendored modules from
node_modules/three/build together and retain the license.

Run `npm test` for gameplay/progression/content checks. With `npm run dev` running,
open `/tools/check-3d.html` for real WebGL checks covering representative levels,
resource disposal, camera projection, swallowing, dynamic objects and fallback.
The renderer falls back to the previous 2D canvas when WebGL is unavailable or
its context is lost. Test performance on physical Android/iOS devices before release.
